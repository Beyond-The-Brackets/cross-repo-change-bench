This pull request modifies the definition of `CFE_MSG_Message_t` from a `union` to a `struct`, and adjusts related code that accesses the message data. These changes are likely to impact any external code that depends on the internal structure of `CFE_MSG_Message_t`, particularly in how it's accessed or used.

Below is an analysis of **which external repositories or files might be affected** by these changes, and **why**:

---

### 🔧 Summary of Changes

1. **Change in `cfe_msg_api_typedefs.h`:**
   ```c
   typedef union CFE_MSG_Message CFE_MSG_Message_t;
   ```
   →
   ```c
   typedef struct CFE_MSG_Message CFE_MSG_Message_t;
   ```

2. **Changes in `default_cfe_msg_hdr_pri.h` and `default_cfe_msg_hdr_priext.h`:**
   - Removed the `uint8 Byte[sizeof(CCSDS_SpacePacket_t)]` member from the union.
   - Changed the union to a struct.

3. **Code adjustments in:
   - `cfe_sb_handlers.c`
   - `ut_support.c`
   - `cfe_msg_sechdr_checksum.c`

   All now use `(uint8 *)MsgPtr` instead of `MsgPtr->Byte` for accessing raw bytes.

---

## 📌 Affected External Repositories and Files

### 1. **cFS (Core Flight System)** – Other Modules Using `CFE_MSG_Message_t`

#### ✅ Files:
- Any module that directly uses `CFE_MSG_Message_t` and accesses its members via `.Byte[]`.
- Any code that assumes `CFE_MSG_Message_t` is a union with a byte array field.

#### 🧠 Why?
Because the type definition changed from a `union` to a `struct`, and the `Byte[]` member was removed, any code that relies on:
```c
MsgPtr->Byte[0]
```
will no longer compile or behave correctly unless updated to cast the pointer as done in the new code.

#### 🛠️ Example:
If another module does something like:
```c
if (MsgPtr->Byte[0] & 0x10) { ... }
```
It will fail because `Byte` is no longer part of the struct.
