This PR fundamentally changes the message handling logic within the cFE core, specifically around the concept of "updating headers" before transmission. The core idea is to separate the concerns of:
1.  **Origination Actions:** What needs to happen to a *newly created* message *before* it's sent out (like setting sequence number, timestamp, generating checksums).
2.  **Verification Actions:** What needs to happen to a *received* message to validate its integrity (checking checksums, etc.). This is now done *without modifying the message*, unlike the old `CFE_MSG_UpdateHeader` which might have modified the message during verification.
